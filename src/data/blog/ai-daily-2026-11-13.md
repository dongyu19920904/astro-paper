Qwen Code 有一件事让我在意：它不是一个你粘贴代码进去、等它回答的聊天窗口，而是跑在你本地终端里的一个代理（agent，可以理解成能主动采取步骤、自己决定下一步做什么的程序）。这两种形式看起来都是"让 AI 帮你写代码"，但它们处理问题的方式不一样。

在聊天框里，你发一段代码，它回一段修改建议，你再复制回去手动替换。每一步都要你转运。在终端里跑的代理，从 README 的说法来看，是它自己能读文件、改文件、跑命令，然后告诉你做了什么。你不用一次次复制，它直接在你的项目里动。

这件事值得停一下想的原因是：权限放得更开，能帮你省的麻烦更多，但你不确认就不知道它改了什么。不是说这样不好，而是用法得跟着变。

## 它怎么知道用哪个模型

Qwen Code 在这一点上有一个具体的特性，README 里直接写了：它支持切换到 OpenAI、Anthropic、Gemini 以及自己的 Qwen API，也能接 Ollama 或 vLLM 这类本地部署的模型，而且"可以在运行时切换"。

这对习惯用命令行的人来说意味着什么？意味着你不是绑死在某个提供商上。假设你平时用的 API 额度用完了，或者你想测一下换个模型效果怎么样，不需要重新装工具，只要改配置就行。这类灵活性在聊天产品里几乎没有，它们一般帮你选好了。

不过切换模型和效果稳定是两件事，能换不代表每个模型接进来都一样好用，这部分还是要自己试。

## README 里有一组评测数字，该怎么看

README 提到在一个叫 SWE-bench Verified 的测试集上，七个版本的 Qwen Code 得分在 76.40% 到 77.80% 之间，用的是同一个模型（Qwen 3.7 Max），共 500 个任务，每个版本跑三次取均值。

SWE-bench 是一套让模型去解决真实 GitHub issue 的评测，可以理解成考题是"这个开源项目里有个 bug，你能修好吗"。76% 以上是一个相对靠前的成绩，放在同类工具里不算低。

但评测能说明的是在标准题目上的表现，不是你自己项目里的真实情况。你的代码库、你的问题类型都和评测集不一样。这个数字可以拿来做横向比较参考，不能直接换算成"用它帮我调试，能解决多少问题"。

我在意的是这组数字怎么来的这件事本身：七个版本、同一个模型、三次重复，这种记录方式比只贴一个最高分要可信一些。至于你的场景会不会得到类似的效果，只有实际跑一次才知道。

Qwen Code 目前标注的是 1.0 Preview，也就是预览版。它的 README 里提到项目仍在活跃迭代，包括用自己的代理给自己提 issue 和提交代码，接口和行为都可能变。这不是阻止你试用的理由，但意味着现在进入的人，配置方式和命令将来有可能跟着变，记下你用的版本号是个好习惯。
