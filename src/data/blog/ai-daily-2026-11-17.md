如果你在给 AI 代理写一个新技能，最担心的事大概是：我花时间做完了，代理却根本加载不了它。这不是小概率，技能文件夹里少一个字段、指令写法不对，代理就会静默跳过，或者在运行时才报错，这时候已经不好定位问题了。

NVIDIA 最近开源了一个叫 SkillEvaluator 的工具，专门用来在技能上线前做检查。这里的"技能"（skill）可以先理解成：你写好的一组指令文件，告诉代理在某种场景下应该怎么做事、能调用什么。把它交给代理之前，你需要知道这个文件夹本身是否符合格式，代理能不能正常读取它。

SkillEvaluator 把检查分成几个层级。最轻的一层叫 harness check，仅验证你的技能文件夹能否被代理加载，这一步不需要调用任何语言模型，也不需要 API 密钥，只是做结构性检查。README 里写得很直接：No LLM inference, No model key, No agent run。检查完几秒钟出结果，告诉你能装还是不能装。

我在意这个逻辑，因为它把一个常见的隐患变得可见。通常你写完技能、推进去，不出问题就继续，出了问题才回头排查。但格式问题往往不会触发明显报错，代理只是没按你期望的方式运行，你很难判断是技能的问题还是任务本身的问题。先用工具确认"能装上"，至少排掉一类可能。

## 分层检查的意思是什么

SkillEvaluator 的分层设计，粗略讲就是：你想检查多深，用哪一层。

第一层（Tier 1）是不依赖语言模型的静态质量分检查，包括上面说的 harness check。README 给出的例子里，一个示例技能跑完得到 88.8/100，默认通过线是 70 分，输出是一份 JSON 报告。这一层不需要 GPU，也不需要注册任何服务，安装工具之后在本地就能跑。

第二层引入了语言模型，用来做更细的评分，比如技能的指令写得清不清楚、有没有语义冲突。这层需要接 API 密钥，工具支持接 NVIDIA 自己的托管端点，官方说符合条件的开发者账号可以免费试用，受访问条款和频率限制约束，具体条件要看 build.nvidia.com 上的说明。

第三层是在实际跑代理的情况下，测量"加了这个技能和不加，任务结果有没有变化"。这层代价最高，也最接近真实答案，但它依赖第一二层先通过。

有意思的是，工具本身建议的顺序就是从第一层开始。README 里提到了先做 quality checks，再做有无技能的对比运行。这个顺序不是废话，是因为如果技能文件格式有问题，根本装不上，后面的测量也就没有意义。

---

这个工具目前的支持级别是 Experimental，官方说明是社区维护、尽力而为，没有服务等级承诺，也不包含 NVIDIA 的企业级支持。如果你在严肃的生产流程里用它，这一点值得留意。

这里值得停一下想想的是：格式检查和效果评估是两件事。SkillEvaluator 能帮你确认技能能被加载、静态质量分通过了，但技能在实际任务里有没有帮到代理、帮了多少，第一层给不了答案。工具的分层设计本身也是在说这件事，能装上不等于有用，这两个问题要分开问。

如果你现在手里有一个正在做的技能文件夹，可以先用第一层跑一次，看输出的 JSON 报告里哪些字段没过。这步不用花 API 费用，也不用等代理真正跑任务，问题出在哪里比较容易看到。
