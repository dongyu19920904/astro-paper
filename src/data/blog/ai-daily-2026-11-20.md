大多数人觉得训练语言模型这件事跟自己无关，不是因为没兴趣，是因为看过几篇教程之后完全不知道第一步做什么。教程要么直接从数学公式开始，要么上来就要你准备一台八卡服务器。

minimind 解决的正好是这个问题：不是让你理解完所有原理再动手，而是先给你一条从头到尾都能跑通的路。

README 里有一句注释值得单独说一下。"两小时"指的是在一张 NVIDIA 3090 显卡上跑完监督微调（SFT）阶段一遍的实测耗时，这不是整个训练流程的总时间，预训练阶段另算，模型本身也只有 64M 参数，大约是 GPT-3 的两千七百分之一。这个数字不是用来让你觉得自己快要造出 ChatGPT，而是在说：规模小到这里，普通人用普通设备也能跑完一遍，知道每步在干什么。

我在意这件事，是因为"能跑完一遍"和"知道发生了什么"之间通常差得很远。大多数训练框架都给你提供高度封装好的接口，十几行代码就能完成"加载模型、加载数据、训练、输出"，整个过程像一个黑盒子，你只看见输入和输出，中间发生了什么完全不可见。minimind 的做法是所有核心代码从零用 PyTorch 写，不依赖那些封装好的高层接口。这意味着你至少有机会逐行去读，知道数据是怎么清洗的，模型结构里每一层做什么，训练循环是怎么写的。

## 读懂代码比跑通结果更难，但这里有个具体起点

这里有一个实际的区分对初学者有用：这个项目覆盖的流程分成好几个阶段，预训练（Pretrain）、监督微调（SFT）、以及各种强化学习方式，还有工具调用和知识蒸馏。预训练是让模型从大量文本里学语言本身，这个阶段数据量大、时间长；SFT 是在已经有基本语言能力的模型上，进一步教它按指令回答问题，这个阶段相对短，也是 README 说的两小时对应的部分。

如果只是想弄明白训练过程是怎么回事，从 SFT 阶段入手比从头读预训练代码更容易建立感觉，因为它的输入输出更直观：给模型一个问题，让它学着给出合理的回答，你可以直接看到效果。

这个项目是 Apache 2.0 协议开源，代码和部分训练数据都公开，可以在 GitHub 上直接看。ModelScope 上有在线体验入口，不需要先配好本地环境就能感受一下训练结果是什么样子。

值得注意的是，64M 参数的模型能力有明确的上限，它能展示训练流程，但输出质量和你每天用的大模型差很多。这个项目的价值在于可以动手读懂、跑通，而不是拿来做正式任务。
