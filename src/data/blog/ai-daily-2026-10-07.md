Claude Code 或 GitHub Copilot 生成一段代码后，终端里滚过几十行日志，关键的错误信息埋在第 47 行。你需要往回翻，重新定位问题出在哪个文件、哪个函数、是权限还是依赖。这种体验在自动化编程流程中会反复出现，尤其是多个智能体协作或长时间运行的任务。

今天 GitHub 上有两个项目在解决同一件事：让 AI 生成的结果真正可用。

## 日志格式需要为人类注意力优化

[i-have-adhd](https://github.com/ayghri/i-have-adhd) 项目单日新增 326 Stars，它为编码智能体设计了一套 ADHD 友好的输出格式。核心改进是将关键信息从冗长日志中提取出来，按优先级和类型分层显示。错误、警告、文件变更、下一步操作各占一块，不再混在时间流水里。

这不是给 ADHD 群体的专用工具，而是承认了一个事实：人的注意力处理不了智能体的完整思考过程。传统日志按时间顺序记录每一步，适合事后排查，但实时调试时你只想知道"哪里错了"和"我该改什么"。

## 图表也需要为审查而非展示设计

[diagram-design](https://github.com/cathrynlavery/diagram-design) 项目提供了 42 种图表类型的独立 HTML + SVG 模板，专门给编码智能体用。它的设计原则是：无阴影、无渐变、无 Mermaid 的混乱语法。每个图表是完整的 HTML 文件，可以直接在浏览器打开，也可以嵌入文档。

我更关心这个细节：独立 HTML 意味着你可以不依赖任何渲染引擎就能看到结果，也可以直接编辑 SVG 代码验证数据。Mermaid 的问题不是功能不够，而是生成的图表需要特定环境才能渲染，出错时很难判断是数据问题还是语法问题。

## 什么时候需要这类工具

如果你只是偶尔让 AI 写几行代码，默认输出格式够用。但如果你在做这些事，输出格式会影响效率：

- 运行自动化测试或 CI 流程，需要快速定位失败原因
- 多个智能体协作完成复杂任务，需要追踪每个智能体的决策
- 生成图表或文档后需要人工审查数据准确性

这两个项目的共同点是：它们不改变 AI 的能力，只改变输出的组织方式。代价是增加一层工具，收益是减少人的认知负担。

## 我的判断

AI 编码工具的下一个瓶颈不在生成质量，而在人的审查速度。当 AI 能生成几百行代码、十几个文件、完整的测试套件时，开发者需要的不是更长的日志，而是更快找到需要关注的部分。

如果你正在用 AI 做多步骤的自动化任务，可以试试这类输出格式工具。它们不会让 AI 更聪明，但会让你更快发现 AI 哪里出错了。这在调试阶段比生成速度更重要。

需要注意的是，这类工具通常需要 AI 工具本身支持自定义输出格式，或者你需要在 AI 生成结果后再处理一遍。如果你用的工具不支持，可能需要写脚本转换格式。
