卖 AI 账号这两年，我越来越觉得自己面对的不只是产品更新，而是一场工作流的根本变化。

最明显的感受来自客服。早期，用户买个账号，我讲个教程，事情就完了。现在不是。用户买了，不会用，卡在某个环节，然后你要花时间解释"这不是我的工具坏了，是你没理解 Agent 是干什么的"。这种理解成本的增加，正在吞掉我本来省出来的利润空间。

Grok Bot 新增的主控 Agent 角色就触发了我的一个长期疑虑。用户不用自己给多个 Bot 分类，主 Agent 自动调度——听起来很爽，但真实场景里，用户其实并不知道背后发生了什么。Bot 怎么分工的？什么时候调用哪个？为什么结果有时候好有时候不好？我要解释这些。

这种解释成本，正在成为我卖账号生意里的隐形成本。

## 自研加开源的思路，对一人公司意味着什么

Higgsfield 那个案例触到了我心里的另一根弦。一个客户从月付 99 美元升到年付 600 万——这不是因为工具本身，而是因为他们自研了商拍图像模型、微调开源模型，用动态路由器管理成本。综合毛利稳定在 80%，企业客户第 12 个月 NRR 超过 300%。

我现在卖账号，是个中间商角色。但看到这个案例，我在想：如果我不只是转卖，而是自研一层什么呢？比如，我自己搭的 Agent 框架能帮客户自动分类任务吗？我能不能基于我卖的账号类型，做一个"账号选型 Agent"——用户描述需求，Agent 自动推荐买哪个套餐，甚至自动生成使用教程。

这不是因为我想做技术产品，而是因为现在的模式已经快到天花板了。账号卖出去，我的工作没完。自研一层自动分发和匹配的逻辑，等于是我在替自己的客服做减法。

但现实是，我现在根本没有多余的线程去做这个。客服、补货、售后、教程维护，已经把我切得很碎。

## 零 API 费用的方案，和我的成本困境

Agent-Reach 这个开源项目能零 API 费用读取全网内容，放在我这里，第一反应是：能不能用这个让我的日报 Agent 不用付费调用 API？

但转念一想，问题可能更深。我现在的成本结构里，API 费用反而不是大头。真正吃成本的是：我要手动补货、手动解释、手动追踪售后、手动维护客服知识库。这些，零 API 费用解决不了。

我更需要的是像 Higgsfield 那样的"动态路由"——能自动判断用户应该被分配到哪个流程，能自动生成对应的教程，能自动处理常见问题。Grok Bot 的主控 Agent 模式实际上就在做这件事，它让用户不用手动分类，主 Agent 来做调度决策。

我要学的，是这种**把手动决策自动化**的设计。

## 下一步，我可能会试什么

先不说大计划，就说最近的打算。我想把现有的账号体系梳理成一个"技能库"——每个账号类型对应什么样的用户需求，什么样的教程，什么样的常见问题。用文档把这些 SOP 定义下来，然后看能不能让 AI 自己去处理 70% 的客服问题。

剩下的 30%，那才是真正需要我动脑子的。

说实话，我现在看 AI 新闻，第一反应常常是："这个能不能帮我卖账号？"但更深层的反应应该是："这个能不能帮我自动化掉那些重复劳动？"前者是生意眼光，后者才是长期活下去的方式。

Higgsfield 的毛利率能稳定在 80%，不是因为他们模型最强，而是因为他们找到了自研加开源、成本控制加 NRR 增长的组合。我没那么大的野心，但逻辑是一样的：**在小生意上也要找到自动化和复制的空间**，否则我永远在被客服和琐事拉扯。

这可能是未来一两个月我真正要做的事。
