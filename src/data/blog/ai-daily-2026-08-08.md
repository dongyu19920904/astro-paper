Vercel 联合 AWS、GitHub、Microsoft、OpenAI 推出了一个叫 Agent Plugins 的跨平台标准，用一个 `plugin.json` 把技能和 MCP 配置统一描述，首批支持 ChatGPT、Codex、Cursor、GitHub Copilot。同一天，北京海淀搞了一个城市规划项目，人类不能直接提交方案，参与者只限 AI Agent。两件事撞在一起，感觉 Agent 从"工具"变成"流程参与方"这件事，今天算是某种节点。而我一直在想的一个问题，又被顶上来了：我店里的客服，什么时候才能被 Agent 接管？

## Agent 进城市规划了，但我的问题没那么宏大

海淀那个项目，[报道](https://mp.weixin.qq.com/s/bFR52i8SZghE12fZJL4rpA)说 Agent 要走完设计、提交、评审全流程，最终成果有机会真正落地。我看到这条的时候脑子里第一个念头不是"哇好厉害"，而是——

这个 Agent 能不能顺便帮我回答"Cursor 换号器怎么用"？

不是在开玩笑。城市规划听起来很高端，但它的信息结构其实比我的售后简单：规则是固定的，方案是结构化的，评审标准是可量化的。我的售后呢？用户的问题千奇百怪，同一个问题能问出十八种说法，而且每个人卡住的地方都不一样。

所以我对"Agent 进流程"这件事是认可的——只是我认可的不是城市规划那个，是我自己店里那个尚未实现的版本。

## Anthropic 没参与 Agent Plugins，我有点微妙

Vercel 这套 [Agent Plugins 标准](https://x.com/Gorden_Sun/status/2085560508082753966)，首批支持的是 ChatGPT、Codex、Cursor、GitHub Copilot，但 Anthropic 没参与，Claude Code 首发不受支持。

作为一个卖 Claude 中转和 Claude/Gemini/Codex 三合一账号的人，这条消息让我有点说不清楚的感觉。

一方面，Anthropic 不参与这类标准这件事，说实话不是第一次了。它一直有点自己走自己路的调性，MCP 是它自己推的，现在别人搞了个新标准，它缺席，这很 Anthropic。另一方面，如果这个标准真的跑起来、被主流工具采纳，Claude 的生态位就会比较尴尬——用户问我"Claude 账号能不能用这个插件"，我怎么答？

这就是卖账号的处境：我不生产任何东西，但上游任何一个生态决策，都会变成我的客服问题。

这种感觉我已经习惯了，但每次遇到还是会皱一下眉。

## 客服自动化这件事，我想了很久还没解决

爱窝啦现在每天销售额大概 3000 左右，利润大概 1000，商品已经能 24h 自助、卡密秒发。听起来挺自动化的，但实际上真正消耗时间的从来不是发货，而是：

用户不会用。

不是不聪明，是教程和产品之间的 gap 永远比预期的大。"收到卡密了但不知道怎么激活""换号器操作步骤我按了但没反应""Claude 三合一是分开用还是一起用"……同一类问题，每天都在问，每天都得答。

我一直在找 AI 客服方案，试过几个，但没有一个让我觉得"好，就它了"。要么太死板，只能回答 FAQ 列表里有的，稍微绕一点就答错；要么需要维护的知识库太重，更新一个商品，十几条教程都要跟着改。

看到这些 Agent 进流程的新闻，有个不成熟的想法：现在的 AI 客服方案，基本上还是"查文档"逻辑，而不是"走流程"逻辑。用户问问题，AI 去检索答案，找到就回，找不到就说不知道。但用户的真实需求往往是：我遇到了一个具体的操作问题，能不能一步步带我走完？

这是两种不同的 Agent 设计。海淀那个城市规划 Agent 走的是"流程参与"路线。我需要的客服 Agent，也应该是这个路线——不是回答问题，而是陪用户走完操作。

这个目前还没有现成的工具能直接给我用。或者说，有，但门槛不低，还没腾出手来认真搭。

## 标准战争我不参与，但我得盯着

Agent Plugins 出来，MCP 还在，以后可能还会有别的标准。这种协议层的竞争，我是局外人，但不是完全不相关。

Cursor 在 Agent Plugins 首批支持名单里。我卖 Cursor 的各种账号——Cursor 独享号、激活器、换号器、无限助手，这些产品的用户就是重度 Cursor 用户。如果 Agent Plugins 跑起来之后 Cursor 的用法变了、用户期望变了，教程和 FAQ 就得跟着更新。

这不是什么大事，但这就是我的日子：上游每动一下，我这边就要跟着调一调。有时候觉得累，有时候又觉得，这种"卖铲子"的位置其实还挺稳——AI 生态越卷，用工具的人越多，生意越有人来。

就是，得一直盯着。不盯着就容易掉链子。
