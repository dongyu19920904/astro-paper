AI 现在越来越会干活了，但这件事对我的意义和你想的不一样。

---

## 自动续跑这件事，让我想到的不是效率

Claude Code 桌面版加了个勾选框，5 小时额度到顶之后，主 Agent 和子 Agent 可以自动恢复，不用手动守着重启。[宝玉在 X 上实测了一下](https://x.com/dotey/status/2088877534859473370)，一个设置项的事。

[Claude Code 自动继续功能截图](https://pbs.twimg.com/media/HP0uf5fWkAA0fWv?format=jpg&name=orig)

我看到这条的第一反应不是"哇这功能好"，而是——这下我又要改教程了。

店里一直有卖 Claude 相关的账号和中转，每次工具有点风吹草动，就会有人来问：之前你说的步骤怎么不对了？我按你说的操作没反应？这个截图是旧的吗？

教程这件事，是我店里最持续的消耗品。不是写一次就完的，每次工具更新，旧截图就会变成售后炸弹。用户不会主动检查文档是不是过期，他们只会发现"按这个操作不行"，然后来找我。

这条新闻对我的意义，其实是：又有一个细节要改。

---

## ChatGPT 能提 PR 这件事，我理解不了，但我理解它的影响

ChatGPT Pro 接 GitHub，可以自己 clone 仓库、生成方案、提 Pull Request。宝玉把仓库地址发过去，[AI 就跑完了整个流程](https://x.com/dotey/status/2089072890104725788)。

我不写代码——或者说，我写的那点东西不算。但我在想：这件事往后走，对我卖的这批工具意味着什么？

Cursor、Windsurf、Kiro、Augment，这些 AI 编程工具，我都在卖。用户买它们，核心原因是"让 AI 帮我写代码"。现在 ChatGPT 直接接了 GitHub，能提 PR 了，那用户会怎么想？他们会不会觉得，我不需要单独订阅编程工具了，ChatGPT Pro 就够用了？

这个问题我暂时没答案。可能 Cursor 还有它的独特优势，可能 Pro 用户真的不多，可能真实体验差很多。我不知道。但我知道的是，每一次大厂整合能力，都会有人过来问我：你这个还有必要买吗？

---

## 用户理解成本，才是我每天真正在消耗的东西

说一件长期困扰我的事。

我的客服压力，其实很大一部分不来自产品问题，而来自"用户看不懂"。

Claude/Gemini/Codex 三合一账号，用起来涉及多个入口、多个额度、多个限制规则，不同模型的限速逻辑也不一样。我写了教程，但教程再详细，也有人看不懂。不是他们笨，是这些产品本身就复杂，而且一直在变。

Claude Code 这个自动续跑功能，从技术上看非常小，就是加了个勾选项。但从用户角度看，它改变了"我要怎么用这个工具"的心智模型。原来要手动守着重启，现在不用了。这个变化，如果我不及时更新教程，用户就会卡在旧认知里。

这就是我最头疼的地方：AI 工具在加速迭代，但用户理解速度跟不上，而我夹在中间，负责消化两边的差距。

工具越聪明，反而售后越重。不是因为工具出问题，而是因为用户没想到"它现在可以这样用了"。

---

## 我一直想做但没做好的事

自动化客服。

这个念头我有了很久了。理论上，我应该能用 AI 搭一套能扛住常见问题的客服系统：自动识别问题类型，匹配 FAQ，处理不了的再转人工。这套东西如果跑起来，我每天能省下大量重复解释的时间。

但实际情况是，我一直在想，一直没真正跑起来。

原因之一是教程本身没完成体系化。FAQ 不是一张表，是一套随产品变化的活文档。我没有一个稳定的知识库，AI 客服也就没有可以用的底子。

原因之二是线程太多。每天真正坐下来做这件事的时间，经常被客服、补货、上新、异常处理切碎。等我想起来，一天又过去了。

ChatGPT 能提 PR，Claude Code 能自动续跑，但我自己的 AI 客服系统，还是一盘散沙。

这个对比，有点讽刺，但也没什么好说的，就是现实。先承认，再找时间拆。
