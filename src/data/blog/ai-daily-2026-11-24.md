Stitch Skills 仓库的 README 里有一句话容易被跳过：这些技能需要 Stitch MCP 服务器配置好并运行在代理环境里，才能正常工作。

这句话的意思是：你在 Cursor 或 Claude Code 里装上这些技能文件，不等于它们就能用了。技能本身只是一组指令，它们调用的实际能力，比如读取 Stitch 设计项目、生成界面稿、上传修改，全部由 MCP 服务器提供。服务器没连上，技能就是一份说明书，代理读得到但做不了事。

MCP 服务器可以先理解成一个中间层，让你的 AI 编程工具能够与外部服务通信。Stitch 是 Google 的一个界面设计工具，它的数据不在你的本地文件夹里，AI 要操作它，就需要通过这个中间层拿到权限和接口。

我在意这件事，是因为"装上就能用"和"装上才能开始配"是两个完全不同的起点。如果你只看到仓库支持 Cursor、支持 Claude Code 就直接去试，会遇到一道门，而且这道门不在技能这边。

## 技能和工具的关系

仓库里的技能大致分三组：设计相关的、构建相关的，还有辅助类的。辅助类里有一个叫 enhance-prompt 的技能值得单独说一下，它做的事是将模糊的界面描述改写成更适合 Stitch 生成的提示词。假设你想让 AI 帮你做一个设置页面，你只知道说"做一个设置页"，这个技能可以将这句话扩展成包含排版、配色方向、交互说明的完整描述，再交给后续步骤生成设计。

这类技能的价值不在于它本身有多复杂，而在于它处理的刚好是用 AI 做设计时最容易浪费时间的那一步：你没描述清楚，AI 给你的东西就不是你想要的，然后你再改，再生成，循环好几轮。先把意图说明白，后面的步骤会顺很多。

不过这里有一个前提需要说清：enhance-prompt 本身也需要通过 MCP 服务器工作，不是单独跑的本地脚本。这不是缺点，只是使用前要确认的条件。

另外，仓库说明里提到，如果你选择单独安装某几个技能而不是全套，要注意技能之间可能有依赖关系，少装了某一个，依赖它的技能就会出问题。README 建议优先用插件方式整套安装，原因就在这里。这类依赖关系不会在安装时报错，通常是在运行时才发现，定位起来比较麻烦。

值得注意的是，这个仓库注明不是 Google 官方支持的产品，出现问题走的是开源社区渠道，不是 Google 的技术支持。

如果你现在正在用 Cursor 或 Claude Code 做界面相关的工作，这个仓库的思路是有参考价值的：把常见的设计步骤封装成技能，让 AI 按步骤调用。但在去试之前，先确认你是否愿意配一个 MCP 服务器，这一步不复杂，但不能跳过。
