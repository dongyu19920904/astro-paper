# 文章的 Markdown 与配图

正文继续使用普通 `.md`，不需要 MDX、内嵌 CSS 或新的 UI 依赖。文章中心、作者事实和来源资格仍按 `BLOG_EDITORIAL_POLICY.md`，排版不能代替内容。

## 文字

普通段落自然长短交替，二级标题说清一个具体问题，三级标题用于必要的细分。关键区别或结论才加粗，不整段加粗。步骤确有顺序才用 `1. 2. 3.`，比较确有相同维度才用表格。不要为了“丰富”每篇硬塞列表、引文和表格。

真实引文使用 `>` 并注明原出处。易误读之处可少量用以下原生提示语法，普通引用不会被转换成提示框：

```md
> [!NOTE]
> 这里放需要单独说明的条件，不能编造引文或经历。

> [!WARNING]
> 这里放具体限制，不是泛泛免责声明。
```

代码使用带语言名的围栏，模板提供语法高亮、滚动和复制。长表格可横向滚动，不缩到难以阅读。

## 图片

```md
[![来源配图：明确的对象或图表说明](https://来源域名/实际图片.png)](https://来源文章地址)
```

链接图会渲染为 figure，显示说明、图源和原图出口；普通 `![]()` 仍支持。图片按自然比例显示，不裁剪研究图、不放大小缩略图、不暗示示意图是实验数据。图源有版权或再使用限制时应遵循其要求；来源链接不是转载许可。

不要使用网页链接充当图，不猜测高清版路径，不插入随机装饰封面、生成的实验图或不存在的截图。来源没有图就留白。加载失败显示原图链接，正文保持可读。

9 月历史补图由 `src/data/articleMedia.json` 的已核对来源清单提供，不改旧正文和发布日期，不在 Astro 构建时新增网络依赖。新的自动文章由个人博客专用 `blogMedia.js` 依据同一来源小节和正文引用自动补图，最多两张，不增加模型调用，已有图不重复。

文末使用 `## 参考资料`，只列实际引用的来源；直接显示，不折叠，不写来源审计报告。
